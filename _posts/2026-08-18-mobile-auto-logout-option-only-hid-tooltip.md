## 현상

매니저 설정의 "모바일 기기에서 접속 시 자동 로그아웃 미적용" 체크박스를 켜도, 모바일에서 유휴 시간이 지나면 데스크톱과 똑같이 자동 로그아웃됐다.

이 옵션이 실제로 바꾸는 것은 "자동 로그아웃까지 남은 시간" **툴팁을 숨기는 것뿐**이었다. 결과적으로 옵션을 켠 사용자는 "안 끊긴다"고 믿는 상태에서, 카운트다운도 못 본 채 예고 없이 튕겼다. 옵션을 끈 것보다 오히려 나쁜 상황이다.

## 코드 근거

`isMobile` / `useMobileIdleTime` 플래그가 소스 전체에서 **툴팁 표시 조건 한 곳에만** 등장했다.

**① 툴팁 표시 — 모바일 반영 O**

```tsx
Number(maxIdleTime ?? 0) !== 0 &&
watch('idleTime') !== 0 &&
(!watch('isMobile') ||
  (watch('isMobile') && useMobileIdleTime === false)) && (
    <Tooltip ...>   // 남은 시간 표시
```

**② 로그아웃 실행 — 모바일 반영 X**

```tsx
case 'idle-timeout':
  setValue('idleTime', Number(message?.seconds ?? 0));
  if (maxIdleTimeRef.current > 0 && Number(message?.seconds ?? 0) === 0) {
    onClickSignOutButton();     // ← isMobile / useMobileIdleTime 검사 없음
  }
  break;
```

`onClickSignOutButton()`은 구독 해제 · 전역 스토어 리셋 · `auth.logout()` · localStorage 갱신까지 수행하는 완전한 로그아웃이다. 즉 옵션과 무관하게 로그아웃이 그대로 실행되고, 옵션은 그저 남은 시간 표시만 감추고 있었다.

## 왜 지금까지 발견되지 않았나

로그아웃 게이트가 `maxIdleTimeRef.current > 0`이다. 확인해 본 운영 서버 4곳이 전부 `maxIdleTime = 0`이라, 클라이언트가 자동 로그아웃을 **한 번도 실행한 적이 없다**. 그래서 이 옵션이 무엇을 하든 차이가 드러날 상황 자체가 없었다.

`maxIdleTime`을 설정한 고객사가 있었다면 "모바일 미적용인데 왜 로그아웃되냐"는 문의가 진작 들어왔을 것이다. 설정값이 결함을 통째로 가리고 있던 전형적인 케이스다.

## 수정 방향

원래 의도로 보이는 A안(코드를 라벨에 맞춘다)이 권장이다. 모바일은 화면 꺼짐·백그라운드 전환으로 유휴 판정이 부정확해 의도치 않은 로그아웃이 나기 쉽기 때문이다.

```tsx
if (
  maxIdleTimeRef.current > 0 &&
  Number(message?.seconds ?? 0) === 0 &&
  !(isMobile && useMobileIdleTime)      // ← 추가
) {
  onClickSignOutButton();
}
```

## 함께 반영해야 할 서버 측 제약

이와 별개로 서버 세션 만료 정책이 바뀌어, 유휴 하한(무활동 12시간)과 절대 만료(발급 후 24시간)가 도입됐다. **서버는 기기를 구분하지 않는다.** 모바일 여부 플래그는 저장·동기화만 될 뿐 TTL 계산에서 참조되지 않으며, 인증 경로에 기기 분기가 없다.

서버가 모바일을 예외 처리하는 방향은 택하지 않았다. 모바일만 무기한 세션이 되면 이번에 막은 구멍이 다시 열리고, 판별 근거인 User-Agent는 위조가 쉽기 때문이다. 따라서 클라이언트에서 A안을 적용해도 모바일 사용자 역시 서버 측 제한(무활동 12시간 · 로그인 후 24시간)은 그대로 적용된다. 헬퍼 문구에 이 단서를 명시해야 한다.

```
모바일 단말기에서 매니저 웹에 접속한 경우, 위에서 지정한 유휴 시간에 따른
자동 로그아웃을 적용하지 않습니다. 다만 보안을 위한 서버 측 제한(무활동
12시간, 로그인 후 24시간)은 기기와 관계없이 적용됩니다.
```

이 문구는 A안(코드 수정)이 반영된 뒤에만 사실이 되므로, 코드 수정과 같은 커밋에 넣어야 한다. (코드 없이 문구만 넣으면 여전히 거짓이다 — 실제로 그렇게 커밋했다가 되돌린 이력이 있다.)

## 재현 방법

1. 매니저 설정에서 "일정시간 이후 자동 로그아웃"을 0이 아닌 값(예: 120초)으로 저장
2. "모바일 기기에서 접속 시 자동 로그아웃 미적용" 체크
3. 모바일 단말기(또는 태블릿 UA)로 매니저 웹 로그인
4. 아무 조작 없이 120초 대기

기대: 로그아웃되지 않음 / 실제: 로그아웃됨. 남은 시간 툴팁도 보이지 않아 예고 없이 끊긴다. 단, `maxIdleTime = 0`인 서버에서는 재현되지 않는다(클라이언트가 로그아웃을 실행하지 않으므로).

옵션이 "무엇을 한다고 라벨에 적혀 있는가"와 "실제로 코드가 무엇을 하는가"가 어긋나면, 사용자는 켜지 않은 것보다 더 나쁜 상태에 놓일 수 있다. 그리고 그 어긋남은 특정 설정값에서만 드러나기 때문에, 운영 환경 전체가 그 값을 안 쓰고 있으면 아주 오래 숨어 있을 수 있다.
