## kim-tigerj — 자체 원격 화면 제어 + 에이전트 커널 근본 결함

**자체 원격 화면 제어 구현 — DXGI 캡처 + Media Foundation H.264 + libdatachannel WebRTC (OR-1703)**.
MeshCentral·RustDesk를 그대로 쓰지 않고 PC(에이전트)→서버→매니저 웹UI로 이어지는 WebRTC 원격 화면 제어를 자체 개발했다. orange.remote.exe가 DXGI Desktop Duplication으로 화면을 캡처하고 D3D11/CPU 색변환·Lanczos 다운스케일 후 Media Foundation H.264(HW MFT + SW 폴백)로 인코딩해 libdatachannel 미디어 트랙으로 브라우저 `<video>`에 실시간 스트리밍한다. 로그인/잠금/UAC 보안 데스크톱까지 재연결 없이 잡는 2프로세스 분리구조를 구현·검증했고, 이 토폴로지가 Chrome Remote Desktop과 동일한 정답 구조임을 리서치로 교차검증했다.

**보안 데스크톱·세션0 상주 + MQTT 시그널링 제품 통합 및 TCP 릴레이 종단 동작 (OR-1703)**.
원격 화면 연결에서 yagent가 MQTT set.REMOTE 명령으로 orange.remote.exe를 Session 0에서 실행·수명관리하고 SDP/ICE를 Orange MQTT 채널로 교환하도록 통합했다(개발용 WebSocket 폐기). 입력 주입·별도 커서 채널·적응형 비트레이트·자동 해상도를 붙였고, UDP를 전면 차단한 기업망(다중 NAT VM 포함)에서도 관리자·노드 양쪽이 coturn:3184에 붙는 양방향 TCP 릴레이(both-relay)로 종단 동작을 완성해 폐쇄망 실전 배포까지 도달했다.

**TURN 크레덴셜·coturn 릴레이 인증 체계 설계 (OR-1812, OR-1752)**.
원격제어가 릴레이를 쓰려면 coturn에 안전하게 인증해야 하는데, use-auth-secret 방식으로 시간 제한 크레덴셜(username=만료 timestamp, credential=base64(HMAC-SHA1(공유시크릿, username)))을 rest-api가 발급하고 coturn이 같은 시크릿으로 재계산·검증하도록 설계해 크레덴셜마다 서버↔coturn 통신을 없앴다. coturn을 nginx·redis·mongodb·mosquitto와 동급의 다섯 번째 시스템 패키지로 정식 편입해 폐쇄망 오프라인 번들 설치·업데이트·제거까지 자동화했다.

**커널 드라이버 프로세스 핸들 누수 근본 원인 규명·수정 (OR-391, OR-415)**.
시스템(PID 4)·백신 등 애플리케이션이 접근 못 하는 프로세스를 실시간 분석하려고 orange.sys로 핸들을 여는데, 커널이 연 핸들의 주인이 커널이라 에이전트가 닫아도 회수되지 않아 커널 핸들 누수와 좀비 프로세스가 쌓였다. ZwOpenProcess로 연 커널 핸들을 ObOpenObjectByPointer로 얻은 요청자 프로세스 핸들 테이블에 ZwDuplicateObject로 복제하고 원본을 즉시 닫는 구조로 바로잡았으며, __finally가 반드시 실행된다는 잘못된 가정으로 새던 ObHn 태그 누수(콜스택 실증)까지 함께 수정했다.

**SLOW JOB 폭주에서 잡 큐 근본 결함까지 — 핸들 11,000 누수 해결 (OR-1647)**.
Agent.log의 SLOW JOB 폭주를 추적하다 PeriodicJob 중복 실행 가드가 CJobQueue의 잠재 결함(GetQueuedCompletionStatus로 통지는 소비하고 PopJob 없이 break해 잡이 고아가 되는 문제)을 드러냈고, 이 때문에 DeleteProcessCache가 멈춰 orange.exe 핸들이 11,885개까지 단조 증가했다. 콜백 begin/end 로그로 hang이 아니라 시작 자체를 안 함을 실증하고, '통지 1개 = PopJob 1회' 불변식 복원·상한·예외 try/catch로 큐를 근본 수정했다.

**sprocess 성능 지표 재설계 + SUID 산출식 재설계 (OR-1340, OR-1564)**.
부팅 누적으로만 보내던 sprocess를 sprocess/sprocess_hourly로 분리해 실시간 누적과 1시간 집계를 독립 운영하도록 재설계하고, 측정 델타가 hour 경계를 걸칠 때 생기는 꼬리 오차를 앞꼬리·뒷꼬리로 분할 귀속시켰다. 또 프로세스 역할 식별자 SUID가 커맨드라인 전체를 반영해 bash 1589개·git 448개가 전부 별개로 쪼개지던 영구 파편화(그룹화율 0%)를, 메타 기반 식별(ProcName+서명주체+제품/회사+FileDescription 등)로 재설계해 실측 6610→679(그룹화율 약 90%)로 수렴시켰다.

**레지스트리→파일 저장소 이전으로 하드복구 환경 대응 (OR-1799, OR-1748)** · **DumpAnalyzer 디바이스 스택 워킹 — 0x9F/0xEA/0x124 원인 드라이버 특정 (OR-1310)** · **EV 코드사인 자동화 사내 서버 (OR-1035)** · **Network Zone 토폴로지 신호 수집 — 게이트웨이 MAC·전체 NIC 확장 (OR-1587)** 등, 에이전트 근본 결함 해결과 배포 인프라 자동화를 같은 라인에서 이어갔다.

## smahn9123 — 서버 데이터 파이프라인 대정비 + 보안

**프로세스 영향도 위젯 서버 파이프라인 구축 (OR-1442)**.
OR-1334 V8 데이터 파이프라인 스펙을 rest-api·service·migrations·package 네 서브모듈에 걸쳐 구현한 대형 작업으로, 별도 systemd 집계 서비스(process-aggregator)와 per-SUID MQTT 구독·ZSET keepalive·구독 cap(10만) 롤백까지 설계했다. Task Manager와 동치되는 CPU 식(작업관리자 35% 통제 실험에서 median ~32% 일치)을 per-doc 계산 후 SUID 단위 $avg로 통합하고, hourly/daily 부분집계 cron과 TTL 정책까지 확립해 dev V8 e2e 검증을 통과시켰다. 프로세스 자원 사용 현황을 회사 전체 수준에서 관측 가능하게 만든 기반 산출물이다.

**process.py 배치 파이프라인 재설계 — burst 시 메시지 손실 제거 (OR-1358)**.
메시지 1건마다 즉시 DB 쓰던 process.py를 receiver/writer 두 스레드로 분리하고 컬렉션별 dedupe 버퍼·백프레셔(큐 20만·drop-oldest)·bulk_write를 도입한 1,206줄 신규 구현이다. 수천 대 노드가 매시 정각 직후 동시 송신할 때 broker에서 메시지가 조용히 유실되던 위험을 제거하고 DB 호출을 수백 배 줄였다. 각 90,000건을 발행하는 정상/burst 스트레스 테스트와 7라운드 코드 리뷰로 종료 정합성(수신=처리+drop)까지 검증했다.

**detect.py 인메모리 캐시화 + 0시 리셋·동시성 정합성 (OR-1010)**.
detect.py 핫패스의 MongoDB aggregation/count_documents 호출을 이벤트당 3회에서 0회로 없애기 위해 (CUID,CGID) 집합·hour별 node 집합·오늘치 집계 3종 캐시를 도입하고, 서비스 시작 시 인덱스 range scan으로 일괄 복원하도록 만들었다. 고볼륨 토픽의 반복 write를 캐시 멤버십으로 가드하고, 0시 일일 리셋을 트래픽과 무관하게 wall-clock으로 보장하며 lock으로 정합성을 지켰다.

**노드 자산 인벤토리 번들 API — 번들·재수집·완료관측 5개 엔드포인트 (OR-1761, OR-1641)**.
노드 관리 위젯이 노드×카테고리마다 개별 호출하던 GET /v1/nodeinfo(노드 1대=7~8요청, 300노드 상한에서 silent truncation)를 gzip+ETag/304 단일 번들 콜로 교체하고 재수집 신호·완료 관측 엔드포인트까지 신설했다. '서버는 판정하지 않는다'는 대원칙 아래 판정 기준이 바뀌어도 서버 배포가 불필요하도록 계약을 프론트와 6라운드 협상해 확정했고, node 컬렉션 기준 순회로 삭제 노드 고아 문서를 배제했다. 전체 스위트 1,238 테스트를 통과시켜 배포했다.

**KISA 시큐어코딩 가이드 기반 서버 코드 보안 검증·보완 (OR-994)**.
KISA 소프트웨어 개발보안 가이드 제4장 기준으로 rest-api·service 코드 20개 취약 항목(하드코드 마스터키·MD5·경로조작·SSRF·CORS 와일드카드·로그인 rate limiting 부재 등)을 CWE로 분류·심각도 평가하고 순차 보완했다. 저장소 접근권만으로 무인증 로그인이 가능하던 평문 마스터키를 제거하고, 500 에러의 예외 상세 노출·평문 DB 인증정보 출력을 차단하는 등 치명적 결함을 우선 조치했다.

**조직도 일괄 로드 삭제 부작용 정밀화 + bulk 최적화 (OR-1435, OR-1439)**.
POST /v3/organization/load로 조직도를 재구성할 때 기존 Group/User 삭제가 유발하던 부작용(진행 중 명령의 영구 pending, Node 비정규화 필드 stale, 중간 실패 시 부분 적재)을 시나리오별로 6개 로드맵으로 해결했다. clear→load_groups→load_users→ensure_unregistered를 단일 MongoDB 트랜잭션으로 묶어 원자성을 보장하고, 1만 단말에서 수 초씩 걸리던 직렬 RTT 패턴을 Beanie bulk_writer 단일 RTT(recompute ~830ms)로 압축했다.

**VM 클론 동시 POST 인증 race condition 봉쇄 (OR-1320)** · **노드 인증 응답 견고성 — 부수 작업 실패가 인증을 깨뜨리지 않도록 (OR-1336)** · **fail2ban 도입으로 SSH 무차별 대입 방어 (OR-1313)** 등, 대규모 조직 운영의 정합성과 서버 보안을 동시에 끌어올렸다.

## SungWoo824 — 68위젯 대시보드 RBAC 프론트 전면 구축

**권한 관리 프론트엔드 구축 — 역할·위젯·엔드포인트·기능 4탭 ACL UI (OR-1357, OR-1314)**.
백엔드 RBAC(역할별 위젯 R/W/D·엔드포인트·부서 접근 제어)에 대응해, 설정 위젯 안에 역할 관리 CRUD·엔드포인트 ACL 아코디언·위젯 ACL 그리드·기능 권한 4개 서브탭을 신규 9개 파일 3,233줄로 구현했다. 로그인 응답의 role·widgetAcl을 AuthContext에 보존해 위젯 패널 목록 필터링과 DynamicComponentLoader의 사전 권한 차단(PermissionOverlay)까지 배선하는, 68개 위젯 대시보드 전반에 권한을 관철시키는 넓은 범위의 작업이었다. 동적 역할 컬럼 생성·색상 피커·드래그 순서 변경·조직도 트리 팝업 등 상태가 복잡한 편집 UI를 다수 포함한다.

**위젯별 403 권한 오류 경계 아키텍처 정비 (OR-1402)**.
기존에는 위젯이 던진 403 예외를 PermissionErrorBoundary가 WidgetTemplate 내부에 있어 잡지 못하고 전체 페이지가 크래시하던 구조적 결함이 있었다. ErrorBoundary를 위젯 부모 레벨(DynamicComponentLoader)로 끌어올리고 TanStack Query가 PermissionDeniedError만 선택적으로 throw하도록 바꿔, 권한 없는 위젯 하나만 오버레이로 격리하고 나머지 위젯은 정상 동작하게 만들었다. 실시간 MQTT 대시보드에서 위젯 하나의 권한 문제가 화면 전체를 무너뜨리지 않도록 하는 안정성의 핵심 작업이다.

**빈 배열 시맨틱 통일 — 위젯 ACL 전원 허용 보안 결함 차단 (OR-1459)**.
위젯 ACL의 빈 배열이 Endpoint/Feature ACL(전원 차단)과 정반대로 '제한 없음(전원 허용)'으로 해석되어, 운영자가 모든 역할 체크를 해제해 차단하려 하면 오히려 전원 허용되는 보안 사고 동작이 있었다. 세 군데의 클라이언트 분기를 length===0 시 차단으로 통일하되 신규 위젯은 자동 전체 체크로 안전하게 처리해, 권한 시스템 전반에 '명시 없음=차단'이라는 보수적 원칙을 관철했다.

**매니저 파일함 UI — 폴더 트리·버전 이력·배포 연동 (OR-1582)**.
매니저가 웹에서 파일을 업로드·버전관리·배포하는 파일함 도메인의 프론트엔드를, 폴더 트리(시스템폴더 섹션·드래그 이동·인라인 파일 표시) + 파일별 버전 이력(적용·롤백·배포됨 배지) + 좌우 리사이저 + 스마트 업로드 다이얼로그로 구현했다. rule/조직도/에이전트 업데이트 등 기존 배포 파이프라인과 연결되는 보관→검토→적용→롤백 흐름을 한 화면에서 다루게 해, 매번 ZIP/JSON을 직접 교체하던 롤백 불가 운영을 대체했다.

- **원격 지원**: 상용 라이브러리 없이 DXGI+Media Foundation H.264+libdatachannel WebRTC 원격 화면 제어를 자체 구현하고, coturn 양방향 TCP 릴레이로 UDP 전면 차단 폐쇄망까지 실전 배포했다.
- **서버 데이터 파이프라인**: 프로세스 영향도 집계 서비스가 회사 전체 수준의 자원 관측을 열었고, process.py 배치 재설계·detect.py 캐시화·노드 자산 번들 API로 대량 노드에서의 메시지 유실과 DB 부하를 근본적으로 걷어냈다.
- **매니저 권한·안정성**: 68위젯 대시보드에 역할 기반 권한(RBAC) 프론트가 전면 구축됐고, 위젯별 403 오류 경계로 한 위젯 장애가 화면 전체를 무너뜨리지 않게 됐다.
- **제품 축 재정의**: 증상을 '이슈'로 승격하는 조건·근거·조치·검증 4요소 축이 세워졌고, 디스크 부족 예방 증상·부팅 성능 자동 측정·BSOD 룰 207개 표준화로 '재고 뒤 안내'가 아닌 '사전 조치'로 무게 중심이 옮겨졌다.
- **에이전트 커널·탐지**: orange.sys 언로드 데드락과 프로세스 핸들 누수 같은 근본 결함이 규명·수정됐고, DNS ETW 이벤트 의미 재정합으로 죽어 있던 실패 탐지가 복구되며 이상 탐지의 신뢰도가 올라갔다.
- **프론트 공통 품질**: 프로세스 위젯 재설계와 AG-Grid 정렬 comparator 전역 도입, 동적 로더 stale closure·i18n 깜빡임 근본 수정, 그리고 홈페이지 SEO 전면 구축까지 실사용 신뢰성과 노출을 함께 끌어올렸다.

3,114커밋의 모양은 '자체 원격 지원 역량과 데이터 파이프라인·제품 축을 동시에 세운 한 분기'다.
