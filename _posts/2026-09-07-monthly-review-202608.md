## kim-tigerj — AI 진단·원격제어·패키징

온프레미스 AI 진단(정팀장), 자체 원격 화면 제어, 패키징·에이전트 기반을 함께 다뤘습니다.

- **진단 응답 계약 재정립 (OR-1784)**: 에이전트 명령 결과 전달 계약을 정립하고 조사 콘솔로 화면을 다시 짰습니다. 질문과 답이 상단에서 겹치던 배치를 정리하고 소요 시간 표기를 바로잡았으며, 동시 처리 상한을 걸어 응답이 몰릴 때 서로 밀리던 문제를 없앴습니다.
- **판정·검색 누출 방어와 회귀 자동 검출 (OR-1779, OR-1780)**: 새 PC를 「오래된 HDD」로 판정하던 원인이던 자료 오독과 모델 캐시 이중 병목을 걷어냈습니다. 인터넷 검색을 서버가 직접 수행하도록 옮기고, 회귀를 자동으로 잡는 guard 스크립트를 두어 같은 오판이 재발하는지 배포 전에 검출하도록 했습니다.
- **첫 응답 속도 단축**: 시스템 프롬프트를 역할 지침만으로 고정하고 상황 정보를 프롬프트 꼬리로 옮겨 세그먼트 캐시가 갈라지던 문제를 막았습니다. 역할별 예열을 더해 새 대화 첫 응답을 60여 초에서 18~29초로 줄였습니다.
- **TURN-over-TCP both-relay 완성 (OR-1703, OR-1752, OR-1797)**: 자체 원격 화면 제어를 이중 NAT VM에서도 통하도록, P2P가 고착되면 미디어 릴레이로 능동 전환하는 경로를 완성했습니다. coturn 서버를 매니저 서버설정에 편입하고 서버팀 설치·업데이트 가이드를 정리했습니다.
- **패키징 배포 사고 수정·하드복구 파일 저장소 (OR-1799, OR-1717, OR-1842)**: 업데이트 설치 중 쓰기 유실로 에이전트가 집단 분실되던 사고를 분석해 자가복구를 보강했습니다. 설정 저장소를 레지스트리 하이브 기반으로 옮기고, zip 단계가 간헐 실패하면서 실패를 성공으로 보고하던 문제를 잡았습니다. 시작 시간은 22.8초에서 4.6초로 줄었습니다.

## smahn9123 — 서버 저장 구조·명령 인프라

백엔드에서 프로세스 저장 구조, 1:N 명령 인프라, 세션·보안 정책을 다뤘습니다.

- **1:N 명령 결과 분리 (OR-1849, OR-1850)**: 명령 결과를 노드 단위 별도 컬렉션(command_node)으로 옮겨, 문서 하나가 16MB 한계에 닿아 결과 전량이 유실되던 구조를 없앴습니다. 결과 스트리밍에서 대상 밖 노드의 응답을 걸러내도록 했습니다.
- **sprocess registry 이관·원자료 보존기간 (OR-2011, OR-2010, OR-2012)**: 프로세스별 최초 관측 시각과 신원 정보를 별도 registry 컬렉션으로 옮기고, 더 쓰지 않는 조회 엔드포인트를 걷어냈습니다. 무한 보존을 전제하던 raw 데이터에 TTL을 넣되 첫 삭제량이 과하면 넘겨 대량 삭제 사고를 막았습니다.
- **세션 만료 정책 정비 (OR-1920)**: 무기한으로 남던 매니저 세션에 유휴 하한과 절대 만료를 넣었습니다.
- **경량 명령 인프라화 (OR-1673)**: 결과 집계가 필요 없는 명령을 위한 표준 통로(Signal Command)를 만들어, 매번 결과 수집 구조를 얹지 않아도 되게 했습니다.
- **노드 제어 통합과 문서 표준화 (OR-1770, OR-2026)**: 명령 대상을 노드 단위 발송으로 전환하고 복수 그룹·가상그룹 제외를 지원했습니다. manager-web 문서 구조를 작업당 워킹셋이 작아지도록 정리하고 수명주기 규칙을 세웠습니다.

## SungWoo824 — 조직도 그룹·권한·서버 모니터링

조직도 1:N 명령, 위젯별 권한, 서버 모니터링을 서버·매니저에 걸쳐 다뤘습니다.

- **조직도 그룹 드래그 재정렬 (OR-1825)**: 서버에 그룹 문서와 순서 일괄 변경 API를 두고, 매니저에서 그룹 머리말을 끌어 순서를 바꾸며 가장자리에서 자동 스크롤되도록 만들었습니다. 55개 커밋에 걸친 작업입니다.
- **기능 권한·원격제어 게이팅 (OR-1900, OR-1911)**: 위젯별 권한 구조를 새로 짜고 관리자 root 계정과 권한을 정비해, 원격제어 같은 민감 기능을 권한으로 통제하도록 했습니다.
- **서버 모니터링 타입 고도화 (OR-1933, OR-1959)**: 서버 모니터링 대상 타입을 정리하고 타입별 판정을 다듬었으며, 지표 라벨을 다국어로 옮겼습니다.
- **계정 열거 방지·v3 detects 엔드포인트 (OR-1959)**: 로그인 응답으로 계정 존재 여부가 새던 것을 막고, v3 detects 엔드포인트를 신설했으며 자원 baseline 판정을 안정화했습니다.

## kimyh-orange — 릴리즈 노트·차트·서버 알림

릴리즈 노트 취합과 매니저 차트 정비, 서버 모니터링 알림을 다뤘습니다.

- **릴리즈 노트 재작성 (OR-1894, OR-1988)**: 1.6.242.0813 회차를 전수조사로 다시 써 빠져 있던 신규 항목을 보충하고, 누적형으로 재구성해 홈페이지에 게시했습니다.
- **노드 확산·부하 차트 정비 (OR-1517)**: 노드 확산 막대가 누적 최대라 한 번 오르면 내려오지 않던 것을 그날 값으로 고치고, 부하 위젯의 Disk·유선·Wi-Fi에 읽기·쓰기를 합친 전체 항목을 더했습니다.
- **서버 모니터링 알림 통합 (orange-monitoring)**: SSL·MongoDB·HTTP 실패를 Slack 알림 하나로 모아, 서버 이상을 놓치지 않도록 했습니다.
- **증상 조치 실행 명세 (OR-1803, OR-1912)**: CPU 과점유·디스크 부족 같은 증상에 대해 종료·예약작업 중지·제거·버전 비교로 이어지는 조치 세트를 정리해 에이전트팀 인계용 명세로 만들었습니다.

## wychoi-orangelabs — 에이전트 설치·연결 종료 탐지

에이전트 설치 재정비와 연결 종료 탐지 오탐을 다뤘습니다.

- **드라이브 독립 설치 (OR-1695, OR-1766)**: 설치 대상 드라이브를 고를 수 있는 설치 파일을 만들어, 특정 드라이브에 묶이던 제약을 없앴습니다. 22개 커밋에 걸친 설치 스크립트 재정비입니다.
- **연결 종료 통계·비정상 종료 탐지 정정 (OR-1949, OR-2000)**: disconnect 통계가 내부 장부에 얽혀 0으로 고정되던 값을 분리하고, 특정 종료 코드가 다른 코드 탐지를 죽이던 회귀를 고쳤습니다. TCP RST 탐지에 레이트 리밋을 넣어 노이즈를 걷어냈습니다.
- **DNS 실패 탐지 복구 (OR-1934, OR-1944)**: DNS 완료 이벤트(3008) 단일 처리로 매치 로직을 정리해, 놓치던 DNS 실패를 다시 잡도록 했습니다.
- **고객사 현장 분석 (OR-1844, OR-1979)**: 현대해상 TCP/DNS 분석과 용인시청 PC 느려짐·멈춤 현상을 현장 데이터로 분석했습니다.

## hja-orange — 매니저 영어화·홈 위젯 재설계

매니저 전 위젯의 영어 로컬라이징과 홈 대시보드 위젯 재설계를 다뤘습니다.

- **전 위젯 영어 로컬라이징 (OR-1925, OR-1937, OR-1935)**: en 로케일을 전면 번역하고 하드코딩된 한글을 걷어냈습니다. serverMonitor·processImpactMap·nodeInfo를 비롯해 위젯 662개를 모두 옮기고, 미번역 2828개를 채웠으며, 화면에 i18n 키가 그대로 뜨던 자리들을 바로잡았습니다.
- **서버 모니터링 위젯 복구 (OR-1938)**: 서버가 주는 'warning' 상태가 타입 정의에 없어 위젯이 통째로 죽던 것을 고쳤습니다.
- **홈 위젯 재설계 (OR-1859, OR-1995, OR-2004, OR-2005)**: 증상 목록·전체 노드 요약·시간대별 증상·장기 미접속 노드 위젯에 디자인 시스템을 입히고 차트를 다시 그렸습니다.
- **고정 노드 위젯 통합·증상 수집 병렬화 (OR-1993, OR-2017)**: 홈에 흩어져 있던 개별 노드 위젯을 「고정 노드」 위젯 하나로 합치고, 시간대별 증상 수집이 24회를 순차로 부르던 것을 배치 병렬로 바꿨습니다.
